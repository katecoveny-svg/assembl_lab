      Variations · site diary

      When the job changes, the record changes with it.

      A variation is a change the client asks for after the quote is approved. The agent re-measures what it adds, re-runs the quote maths and shows the difference; the same named person approves it, and the receipt chains onto the quote's. The site diary is the stub of a record that follows: who decided what, when, and which photos were asked for.

        What stays with people

        • The scale. Tools default to the sheet's nominal scale and say so; a person confirms it before measurements count.
        • The rates. Nothing proposes a price. The builder's own sheet is the only source; the defaults are labelled illustrative.
        • The risks. defect_register proposes; a named person picks which become provisional sums.
        • The quote and every variation. draft_bid and variation return drafts at authority act with approval. A named person sends, changes or withdraws, and each decision is a hashed receipt chained to the last.
        • Compliance. consent_check and code_checks point at MBIE's pages. The council decides; the tool never does.

        Pattern: enquiry → agent steps with tool calls and records → a named person approves → chained receipt. Built clean-room by the assembl lab; no third-party takeoff code or assets.
