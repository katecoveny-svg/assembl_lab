    Agent-ready · the same four tools over MCP

    An assistant can call the same desk.

    The page and the endpoint share one geometry and one condition library, so a builder's own assistant (Claude, ChatGPT, anything that speaks MCP) measures the same plan the person sees. It is stateless and Simulated: the demo sheets only, and drafting a bid never sends one.

    Endpoint

    POST https://assembl-lab.vercel.app/api/takeoff/

    Streamable HTTP, JSON responses, no sessions, no auth. initialize, tools/list, tools/call, resources/read (takeoff://plans, takeoff://conditions, takeoff://sheets).

      Try it, live

      Lists the tools, then asks find_rooms for A101 and draft_bid for two lines. Read-only: a request, a record, a hash.

      {"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"find_rooms","arguments":{"sheet":"A101"}}}

      What stays with people

      • The scale. Tools default to the sheet's nominal scale and say so; a person confirms it before measurements count.
      • The rates. Nothing proposes a price. The builder's own sheet is the only source.
      • The bid. draft_bid returns a draft at authority level act with approval. A named person sends it, changes it or withdraws it, and each decision is a hashed receipt.

      Pattern: enquiry → agent steps with tool calls and records → a named person approves → receipt. Built clean-room by the assembl lab; no third-party takeoff code or assets.
