# Assembl 3D experience design brief

## Direction and approved baseline

Continue the approved Blender quality across Assembl learning machines and business simulators. Keep the current [claw](https://assembl-lab.vercel.app/study/m/claw.html) and [slushie](https://assembl-lab.vercel.app/study/m/slushie.html) as accepted. The pastel direction applies to future work, not a retrospective repaint.

Use cream, white, soft lilac, blush, mint and powder blue; lighter structural accents; restrained navy labels; and existing product tokens. Aim for premium, calm, editorial clarity. Avoid canary yellow, glowing AI robots and clutter.

## Real editable 3D

Build detailed, editable geometry with convincing proportions, coherent spatial relationships, construction detail and credible materials. Flat, low-detail approximations are not the benchmark. Never present generated imagery as working 3D.

Execute reproducible Python scripts inside Blender. Deliver `.py`, `.blend`, rendered PNGs and optimised GLBs, with named parts, correct units, intentional pivots and documented interaction contracts. Set mesh, material, loading and resource budgets.

Review offline Cycles renders and interactive browser output separately. Simplify browser glass honestly where necessary; an offline render does not prove runtime quality. State simulation limits: do not imply real contact physics, accurate fluid dynamics or manufacturing-grade CAD without evidence.

## Learning machines

Create original English-language guided explorations inspired by `lab.tongjiang.app`, without copying code or assets. Serve New Zealand children, teens and teachers through open, no-signup access, age-appropriate content, accessibility and useful teacher embeds.

Give the object a generous canvas and keep touch controls compact. Structure discovery around **Explore → Predict → Investigate → Explain**.

Learners should change meaningful variables, compare outcomes, retain immutable A/B evidence and reflect without grading. Preserve existing authoritative science and maths models, units and challenges. One model must drive visuals and readouts; never duplicate competing physics. Verify curriculum alignment and version claims separately.

## Business simulators

Apply the same visual standard to dealership, service and parts operations; retail and grocery; and home, energy and building workflows. Represent actual assets, journeys, operational states, options and consequences, not decorative industry scenes.

Structure assistance around **Intent → Context → Recommendation → Approved action → Proof**.

Make human approvals, limits and real partner API permissions explicit. Clearly distinguish live, simulated and proposed information or actions. Never invent ROI, clients, completed actions or evidence.

Use Business Genome and shared runtime configuration rather than a bespoke LLM for each scene. Show how useful work removes friction; do not force learning-machine interfaces onto business dashboards.

## Interface and continuity

Prioritise a useful canvas, not a tiny faint object surrounded by forms. Keep home pages, cards, navigation and typography consistent. Use properly framed asset renders as thumbnails, not cropped webpages.

Support 320px and 375px mobile layouts, keyboard operation, visible focus, reduced motion and honest graphics fallbacks. Preserve experiment state across graphics changes and navigation; define explicit reset behaviour. Motion should explain mechanisms, communicate state or support actions.

## Verification and delivery

Inventory existing machines, then improve them in reviewable batches without rewriting their scientific models.

Follow **Benchmark render → Rig and export → Model integration → Visual and functional QA → Review → Approved release**.

Run model, unit and integration tests. Inspect actual desktop and phone browser experiences, including loading, interactions, accessibility, state preservation and failure paths. Validate asset pivots, units and resource budgets. Report precise coverage; never claim physical-device or AR verification unless performed.

Retain scripts, editable scenes, GLBs, renders, provenance and reproduction instructions. Make assumptions and rendering compromises reviewable. Do not introduce paid services, credentials or unapproved production changes.
