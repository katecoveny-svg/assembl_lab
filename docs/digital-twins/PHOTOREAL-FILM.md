# Photoreal: baked light and the fly-through film (first version)

Status: **working, first version** (22 November 2026, branch `agent/film-1122`). A visualisation, not a photograph.

The lab's 3D page (`/plan-studio/twins/drop/`, sample plan `hero.plan.json`) gains a **Photoreal** switch and a film
renderer. Light is traced through the model's own geometry; every pixel of a still or film frame is rendered from the
model. Nothing is generated by an image or video model, and no photograph, scanned texture, HDRI or downloaded model is
used in the photoreal look.

Credit: the method follows **room-at-dawn** by Leon Lin (MIT licence, <https://github.com/leonxlnx/room-at-dawn>): a CPU
path tracer that bakes irradiance and its dominant direction per vertex, materials patched to read it, contact AO,
bloom and a filmic grade, and an offline renderer that averages jittered sub-frames. Parts adapted from its
`src/bake/*` and `src/core/gi.js` carry its MIT notice in `photoreal/bakeCore.ts`; the rest is written for this page
(three.js r187 node materials, WebGPU with the WebGL 2 fallback, a building in sunlight rather than a room at dawn).

## Use it

- On the page: **Photoreal** (card above Stills). If a bake made earlier for this exact geometry is on the server
  (`drop/twin/bake/hero.gi.bin`) it loads in a few seconds; otherwise the page traces the light itself in web
  workers (about 6 minutes on 2 cores; faster with more). If the browser cannot, the usual view stays and says so.
- `?photoreal` on the page address opens in the baked look.
- Tools (`tools/film/film.mjs`, Node 22.18+, Chrome, `playwright-core`, ffmpeg):

```bash
node tools/film/film.mjs bake  [--spp 64]                    # trace the light (page exports the scene, node traces it)
node tools/film/film.mjs stills --photoreal --out shots/     # the five views, jittered sub-frames averaged
node tools/film/film.mjs film  --out films/flythrough-v1-1080p.mp4 --w 1920 --h 1080 --samples 8
node tools/film/film.mjs film  --out films/flythrough-4k.mp4 --w 3840 --h 2160 --samples 16 --crf 16   # 4K master
```

Add `--soft` on a machine without a GPU (SwiftShader software rendering, as on assembl's build box).

**On a Mac with a GPU, the whole 1080p film in one command** (from the repo, after `npm i -D playwright-core` and
`brew install ffmpeg`; nothing was run on anyone's computer to write this):

```bash
node tools/film/film.mjs bake && node tools/film/film.mjs film --out films/flythrough-v1-1080p.mp4 --w 1920 --h 1080 --samples 8
```

## How it works

| Step | File | What it does |
|---|---|---|
| Choose and tessellate | `photoreal/bake.ts` | The house, fit-out, site works and ground near the house receive light. Big faces are split (conforming edge splits, no T-junctions) so light can be stored per vertex: floors 0.12 m, decks 0.3 m, walls and ceilings 0.25 m, cladding 0.4 m, framing 0.8 m, roof 1.2 m, LiDAR ground as surveyed. Vertices are welded into light points. |
| Occluders | `photoreal/bake.ts` | Every triangle within 60 m: the house, the ground, planting, and the bush. Dense bush (millions of leaf triangles) counts as one box per tree that lets about half the light through; the live sun's shadows still use every leaf. |
| Trace | `photoreal/bvh.ts`, `bakeCore.ts`, `bakeRun.ts` | Own BVH (binned SAH). Pass 1: full paths (sun by next-event estimation at every bounce, from a soft sun disc; glass passes 88 %, foliage 35 %). Smoothing on the mesh graph. Pass 2: a final gather that reads pass 1 where its rays land. Stored light = sky + every bounce; the direct sun is drawn live with a sharp shadow map. Each light point draws its random numbers from its own index, so the bake is the same however it is split (tested). |
| Sky | `photoreal/sky.ts` | The page's painted day-sky colours, glow round the real sun, calibrated so the open sky gives 0.18 of the sun's irradiance on a level surface (clear to lightly hazy coastal day). The same sky lights the reflections. |
| Materials | `photoreal/giMaterial.ts` | One material shape for every receiver (colour, normal and roughness maps), whose diffuse light is the bake, steered by its direction so normal maps still shade; reflections from the sky. A handful of shader programs for the whole house (it matters in software rendering). |
| Surface detail | `photoreal/detail.ts` | Surfaces with no texture get a micro-structure in normal and roughness from the asset library (`library/ptex.ts` via `library/mats.ts`: linen weave, bouclé loops, oak grain, trowelled plaster, brushed metal, glaze, stone). Bark comes from the library too. Drawn here, because the library has no generator for them: deck boards, weathered framing boards, coil-coated roof steel and the forest floor, which replace the scanned photographs and the aerial photo the normal view uses. |
| Props | `photoreal/props.ts`, `vessel.ts` | The library's folded throw (`throwBlanket`: three layers with height-field wrinkles, chunky knit) on the sofa's end seat in place of the fit-out's plainer throw, and a sculpted stoneware vessel on the coffee table (a signed-distance shape meshed by the library's marching cubes, in its crackled glaze). Both proposed. |
| Picture | `photoreal/photoreal.ts` | Contact AO from the scene pass's depth and normals (faded where sunlit), gentle bloom, a light grade (white balance, saturation, contrast, vignette), AgX tone mapping. Indoors the camera opens up and white-balances from the light measured on the painted walls. Diagram lines (boundary, contours) are hidden. |
| Frames | `photoreal/capture.ts`, `path.ts`, `flythrough.json` | Each frame averages sub-frames with sub-pixel jitter, a thin-lens aperture (focus on the look point) and times across a 180° shutter. The bush is culled to each frame's view, and trees within 1.8 m of the camera path are left out so the camera never flies through a trunk. Caption on every frame. |

## What is from the drawings and what is assumed

| In the picture | Source |
|---|---|
| Walls, openings, rooms, decks, roof form and pitch, floor level | the sample plan model (`hero.plan.json`, scaled from its sheets) |
| Ground shape, the clearing, tree positions and heights | LINZ LiDAR in the plan's site block (not survey-grade) |
| Sun position | computed for the site's latitude and the date and time on the page |
| Sky brightness and colour | assumed (calibrated ratio above) |
| Materials and colours: cladding, joinery, decking, glass balustrades, linings | the plan's finish schedule where it names them; textures drawn in code, colours assumed |
| Furniture, linen, styling, the throw, the vessel | proposed by assembl, built in code, placed by rules from room names |
| Planting and bush species (kānuka, pōhutukawa, ponga, harakeke, ferns) | proposed native planting; species not surveyed |
| Forest-floor surface | drawn in code (the normal view uses the LINZ aerial photo) |
| The car | proposed |

No loaded GLB is in this scene: the furniture library (`library.ts`) only fills slots for as-built models; the sample
plan is furnished entirely in code. The normal view uses scanned photographs (Poly Haven / ambientCG, CC0) for deck
boards, roof steel, framing, bark and forest floor; the photoreal look replaces every one of them with drawn textures.

## Measured (assembl build box: 2 CPU cores, no GPU, SwiftShader, 6 GB memory shared with other jobs)

See the report of 22 November 2026 in the pull request for the full table. In short: the bake traces 775,016 light
points against 1,578,128 triangles in 371 s on 2 threads (BVH 4.6 s, first pass 130 s, gather 236 s; 64 samples), after
29 s of page export. The bake file is 4.65 MB (light RGB9E5 + direction, 6 bytes a point): **too big to commit**, so it
is made by the build step above (`.gitignore` keeps it out); without it the page traces in the browser.
