# assembl lab · Plan Studio (plans in, a model you can trust out)

Public landing page at `/plan-studio/` (`index.html`, `css/landing.css`, images in `media/`); the working studio is at `/plan-studio/studio/`.
Every picture on the landing page is output from the fictional demo hall. The architecture lab wears the assembl point-cloud look (`lab/pc/engine.js`): the landing hero is the demo hall as a live point cloud, the studio's model view defaults to a point cloud (Solid one tap away), and the point-cloud page draws through the shared light pipeline. Real artefacts (the PDF being read, the A3 sheets, the code list, the Blender render, the deck) stay framed as what they are. Static HTML, CSS and ES modules; three.js r170 from `/assets/vendor`, pdf.js 4.10.38 from the lab’s pinned, same-origin /architecture/vendor/pdfjs/ copy.
One project model (`js/model.js`, JSON) is the source of truth; the 3D scene, the code pre-check, the working drawings, the exports and
the client presentation are all derived from it and refresh on every edit.

| File | What it does |
|---|---|
| `js/model.js` | The schema, the fictional demo (Tōtara Grove community hall), geometry helpers, revision snapshots and diffs. Every element carries `ev` evidence: `src` drawing / text / ai / user / demo, `conf` 0–1, `note`. |
| `js/read.js` | Reading a plan. A CAD-exported PDF is measured, not guessed: pdf.js gives every path and text run; each path is tagged by how it is painted (dark poché, light room tone, coloured annotation, hairline, or a stroke with its weight). Walls are pairs of parallel wall-poché (or heavier-stroke) edges a wall-thickness apart, merged along their run; the building is the largest connected cluster; openings are gaps in a run (a door needs a leaf line or a true-radius swing from a gap end); rooms come from the labels in the text layer. The scale is read from the sheet ("1:100") and a person confirms it. |
| `js/code.js` | The NZ Building Code pre-check: deterministic rules, re-run on every edit. Each result has a status (pass, fail, needs info, out of scope), the clause, document, edition, measured value and limit. A rule whose figure was not confirmed against the current MBIE document (`verified: false`) can never pass. Advisory only. |
| `js/drawings.js` | Working drawings as SVG (A3): plan 1:100 with grids, dimensions, door swings and room tags; four elevations and a section, each at the largest standard scale that fits (decks, piles and any roof shape included; the section cuts across the roof's fall); the code schedule. Title blocks carry the MBIE minimum fields. Revisions cloud whatever changed since the last issue and fill the revision table from the model diff. |
| `js/scene.js` | The 3D model (walls cut around openings, glazed gable, roof, furniture), day / golden hour / dusk light, exact-size stills with the provenance label burned in, recorded flythroughs (MP4 or WebM), the depth pass that drives AI enhance. |
| `js/materials.js` | NZ materials. Only maker-published values, with sources; conflicting documents shown as a range; every screen colour marked approximate (COLORSTEEL publishes LRV and TSR, not RGB). Māori design is reserved for engagement with mana whenua and the artists, never a texture. |
| `js/exports.js` | IFC4 (validated with IfcOpenShell: 0 schema issues on the demo; evidence in `Pset_assemblEvidence`), DXF R12 with CAD layers, project JSON. |
| `js/points.js`, `js/points-page.js`, `points/` | The model as a point cloud (`/plan-studio/points/`): every point is sampled from the true model's surfaces (area-weighted per triangle, plus crisp points on every hard edge, room floors, and scanner-style ground rings), so it is exactly as accurate as the model; the page says "sampled from model … · not a scan". Colour by scan light, material, the NZBC pre-check or evidence; assemble, scan sweep, explode, plan cut; 0.5 / 1.5 / 3 M points; 4K stills and recorded orbit clips. All motion runs in the vertex shader. The studio hands its current project over in session storage; a project JSON can be opened on the page; nothing is uploaded. |
| `js/present.js` | The 16:9 client presentation (cover, the building, approach, plan, elevations, materials board, pre-check summary, next steps). |
| `../api/plan-read.js` | A raster plan (scan, photo) read by Claude vision with structured output; everything it returns is `src: "ai"`. Needs `ANTHROPIC_API_KEY`. |
| `../api/plan-render.js` | The paid extras through fal.ai, always driven by the true model. Stills: photoreal edit or depth-locked. Hero clips: **FLUX 3 Max keyframes-to-video** (fal's "alligator"; the default: four exact stills of the model rendered along the camera path are pinned to frames of the clip and the AI fills only the motion between them; a cheaper FLUX 3 draft previews the same keyframes), **Wan VACE depth** (follows the depth of a guide clip recorded through the model, uploaded with a signed URL), and **Hailuo 02** or **Kling 2.6** from a single still (motion invented, labelled "illustrative motion"). Every preset shows fal's published price first (or says it is not confirmed), needs `confirm: true`, forwards only allow-listed fields, and counts toward a daily cap. Endpoint ids and fields were checked against fal's OpenAPI schemas on 6 Nov 2026. Results have "AI-enhanced visualisation" burned into every frame. Needs `FAL_KEY` (not set yet). |
| `../tools/plan-studio/render_blender.py` | Hero stills in Blender Cycles from the exported GLB: physical sky and sun, real-scale material shaders, day and dusk. |

Free first: stills, the client view set (street, two corners, rear and interior in one light), flythroughs and Blender hero stills cost
nothing. The AI step is for the occasional hero image or clip. Materials start from a look (Bach, Light weatherboard, Metal, Timber
shiplap): each look is a set of real product selections, never a style prompt.

Turning on hero clips: add `FAL_KEY` to the Vercel project (optional `PLANRENDER_DAILY_CAP`, default 60 jobs a day). Before a client job,
open each preset's fal.ai model page and confirm the endpoint id, its input fields and the price: they were gathered in Nov 2026 from
fal.ai and third-party listings, and they move.

Tests: `node --test plan-studio/tests/*.test.mjs` (the demo, the pre-check, the drawings, IFC/DXF, reading `tests/fixtures/demo-plan.pdf`:
12/12 walls, 9/9 rooms, openings at their exact positions; and the render route against a mocked fal: nothing is spent).

Honesty rules: the pre-check never says "compliant" or "approved"; renders say which model revision they show; AI output says so on the
image; screen colours are approximate. Client drawings uploaded for a pilot stay in the browser and are never committed to this public repo.


## Compare a source drawing with its model
1. Open **Plan Studio → Try a sample drawing**, or drop a vector floor-plan PDF. This reader uses the first page only, not a construction-document set. A sheet with no usable walls and rooms is not a buildable input. A photograph has a separate, explicitly opt-in AI reading and never starts this measured workflow.
2. If a written dimension is available, open **Set scale from a written dimension**. Match its endpoints to the selected wall's centreline; enter the span in mm. This recalibrates the single-scale sheet. Do not use an external face, a partial dimension or a different-scale detail. Only the chosen span has been checked; the rest remains scaled. Calibration, wall/opening evidence and assumed verticals remain in the exported Studio JSON.
3. **Build the model from this → Open model study** first shows the warm cutaway on a display plinth. Its floor and lighting are presentation-only. Select **Compare drawing** for the registered split and the measured wall extents. Drag the divider or use the native slider/arrow keys. Both halves use one orthographic camera. The original PDF texture is positioned by PDF page corners, page transformation, the model origin and metres per point. The rose shader draws a one-metre grid only on the model side; its plum cutaway palette is for inspection, not an actual finish specification. Folio dimensions are wall-centreline extents, not roof or survey dimensions. The larger rose board and temporary presentation materials are disposed when you leave the folio. No picture is stretched to match an attractive framing. With the fictional built-in hall only, the diagram is explicitly labelled as model-derived linework.
4. **Build sequence** shows the drawing, floor, walls, openings, roof and selected finishes. Scrub or explicitly press Play. Each step reveals existing scene groups. The sequence illustrates the model; it does not certify construction methods, sills, height, roofing, structural sizing or consent compliance. No source texture or presentation-only mesh is exported.
5. **Explore the finished model** restores regular orbit, interiors and material editing. **Prepare this model for a walkthrough → Open walkthrough** sends the complete GLB, including the roof and element extras, through the existing same-device IndexedDB handoff to the native Twin viewer. It is a one-time device-local link, not a client share URL.
6. For a reviewed **assembl.plan-model.v1** JSON, choose the original file in Intake. Studio counts its existing wall/opening source notes and opens it unchanged in the native multi-building viewer. It does **not** flatten the reviewed twin into Studio’s distinct **assembl.planstudio.v1** geometry, claim it has the source PDF, or reconstruct a wall-by-wall sequence from an arbitrary GLB.

## Proposed door moves (local)
Open **Model → Move a door** or use the public fictional demo at `studio/?sample=door`. Choose an existing door, enter its new centre distance from the same wall’s start in m or mm, and preview. For the sample: door D4, enter **8.2 m**. The first view is the real scene surrounding the door. It uses temporary copies of the existing Studio model and one fixed camera. Press Original or Proposed, or swipe the frame to compare them; only the frame is wiped, never the geometry. Floor, trim, lighting and open leaf position are presentation choices, not edited design or IFC properties. In **Details**, the drawing rows share a registered scale and the lower row accepts a tap or drag, rounded to 50 mm. An accessible whole-wall slider also proposes positions, and **Enter an exact position** supports individual millimetres. **Preview move** or dragging does not apply a change. The project, its evidence and exports do not change in preview. No script or external agent is executed; the local proposed command is checked against wall ends, other openings and modelled junctions.

**Apply door move** changes that same ID’s position and records the person’s approval separately from original drawing evidence. Existing drawings, model and normal IFC export update from the canonical model. Download under its unissued draft name unless the project matches an issued snapshot. Undo restores the previous position and evidence while it is still the last edit. A changed model or issued revision makes a pending proposal unusable. None of these checks imply consent, structure, access, fire egress or door swing clearance.

The proposal/check/approve separation is inspired by [MutinyBIM’s documented scripting workflow](https://github.com/permitzip/mutinybim/blob/main/docs/SCRIPTING.md); implementation is original and intentionally supports only one same-wall door move at a time.

## Proposed native planting in Plan Studio
Open **Model → Planting brush**. It uses the plan's existing local metres, north-up ground projection and assumed floor-to-ground level. Start with the fictional sample at `studio/?sample=planting`, or, for a vector PDF, use **Set scale from a written dimension** in Plans and build the model. Merely reading a printed scale, a raster file, or calibrating the model outside this tool does not unlock brush mode. The separate fictional QA plan uses a written 9,200 mm south wall; no second PDF is bundled with the tool.

- Choose **Draw bed**, tap the corners of the intended soil polygon, then **Finish area**. There is no automatic outline or subdivision. Mark any additional paths with **Draw path or no-plant area**. Roots are blocked by the building/slab envelope, modelled walls and decks, the shown paved approach, modelled hardscape, and your exclusions. This is an assumed flat ground surface, not survey or planting consent guidance.
- Paint or erase with a mouse/touch sweep and a metric radius. The selected species uses a fixed placement grid, a deterministic seed and a spacing rule; three lightweight native silhouettes are provided. With **Focus plan**, arrow keys move a half-metre at a time and Space places a corner or brush stamp; Escape exits. Undo reverts the last completed change or sweep in the open session.
- **View bed in 3D** returns to the existing 3D model and focuses the planting. The brush uses the same renderer and a separate proposed instance layer. None of these objects change the canonical model, IFC, GLB, drawings or code evidence.
- **Download planting JSON** saves a versioned, local-frame file for the calibrated plan. The normal **Project JSON** includes it separately as `proposed_planting`. To restore either file, load the same calibrated plan, open the brush, and use **Load planting JSON**. The painting, save and load steps never upload a file. No cloud project write or autosave is introduced.

**Layered native mix** adds a canopy accent (tī kōuka), structure (harakeke) and a lower coastal toetoe matrix across the brush footprint. It uses the same calibrated metric ground and exclusions as the single-species brush. Spacing and available ground determine what is actually accepted; applying a different mix to an occupied area never replaces existing plants. The sample-only **Try the layered sample bed** is explicit, reversible and unavailable once a bed exists. Those ideas were informed by the local Aotearoa Planting Studio v2 authoring demonstration; its code, private data, built demo, wildlife, terrain/address import, assets, weights and estimates are not redistributed.

**Plant schedule** opens on demand and shows project-wide accepted quantities and shares, with a CSV matching the table. It does not represent bed ownership, an estimate, planting suitability or a supplier specification. The ordinary proposed JSON remains the source for positions; no new export includes proposed elements in IFC or GLB.

**Season look** is an optional illustrative view. It shows spring flowering and summer seed detail on the same plant positions without changing a saved plant, quantity, model dimension or surveyed object. Species/source links: NZPCN [harakeke](https://www.nzpcn.org.nz/flora/species/phormium-tenax/), [coastal toetoe](https://www.nzpcn.org.nz/flora/species/austroderia-splendens/) and [tī kōuka](https://www.nzpcn.org.nz/flora/species/cordyline-australis/). Harakeke and coastal toetoe provide the seasonal variation in this slice; legacy generic toetoe is not mapped to a species or a flowering calendar. These are example months, not an exact site forecast.
